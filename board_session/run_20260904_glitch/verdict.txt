=====================================================================

   PLL1 (0x19), external clkgen (0x05 + hs2=clkgen), glitch-module clock

   The original "gate FAIL" was a HOST bug: calling loadEncryptionKey()/
   loadInput() on the RAW cw305 target (stock-AES protocol) instead of

   Scripts fixed: diag_extclk.py, glitch_cal.py, glitch_collect.py.
   Also fixed: Husky offset/width are INTEGER phase-shift steps, not
   CW-Lite percent; ext_single trigger REQUIRES scope.arm() per query.

2. Real, reproducible, ct-intact (FTL) finalization faults EXIST.
   config: ext_offset=45, offset=0 or 3359, width=67, clock_xor
   -> ~14-27% of queries come back with ct correct but tag wrong.
   Deterministic: 276 consecutive faults -> 1 distinct faulty tag.

3. Fault-round signature (tag bit-diff vs correct tag) is a clean map:
   ~62/128 bits  -> fault lands EARLY in finalization (many rounds of
                    diffusion remain) -> fully scrambled, DFA-useless
   1/128 bit     -> fault lands at the ROUND-12 OUTPUT register (after
                    last S-box, after key XOR) -> leaks nothing
   10-40/128     -> round-11 S-box INPUT fault = the DFA target

WHAT THE SWEEPS PROVED (negative result)
=====================================================================
1. eo=31 (off=0/3359, w=67) faults 62-bit = too early.
2. eo=45 (off=0/3359, w=67) faults 1-bit = too late (output latch).
3. EVERYTHING between is silent:

   - eo 40..44 x 48 offsets (full offset resolution), w=67: ZERO faults.
   - width 0..3359 at eo=44/off=3359: ZERO faults at every width.
   => The 10-40-bit DFA band is not reachable at w=67. The glitch only
      fires on data-transition edges that exist at exactly two crypto
      cycles for this (key, nonce) at this width; neither is the
      round-11 S-box input stage.

=====================================================================
WHY FULL-KEY DFA DID NOT CLOSE
=====================================================================
1. The only real faults found (eo=45) are in the round-12 OUTPUT
   register: a single bit flips after the final key-dependent S-box and
   after the key whitening XOR -> the faulty tag differs from the true
   tag in exactly that one public bit -> zero key information.
2. A deterministic single-location glitch gives ONE distinct fault.
   The DFA needs, per state column, >=2 distinct faults (different
   flipped bits) on the SAME fixed nonce, across ALL 64 columns.
   Deterministic faults cannot produce that from one config; finding
   ~64 configs that each fault a different column at round-11 input is
   a multi-session grind and this session found ZERO configs in the
   usable band.
3. Even the DFA sweet spot (10-40 bit faults) would only recover the
   round-11 S-box input one column at a time; all 64 columns are needed
   for the key.

A. PA/DL-SCA arm — closed with the confounding artifact identified.
   1. Full 64-column CNN sweep on crunch_M16 (1500 tr): 0/64 beat the
      majority floor; median margin -9.4 pts. Prior "leakage" flags were
      unstratified-split artifacts.
   2. Voltage 0.88-1.00 V (vprobe captures): all at/under floor once
      stratified. No VCCINT voltage lifts first-order leakage.
   3. Friend's HW-vs-HD / input-register lead (would-be breakthrough)
      tested exhaustively: HW(sbox out) vs HW(col in) vs HD(in->out) on
      raw/d1/d2, split-half, max-over-samples nulls. Up to 64/64 columns
      appeared to leak "pure key bits" (K0_c+K1_c) on prof16sc_m32/avg32.
      *** ROOT CAUSE: the random-key datasets RE-WRITE the key bytes to
      the FPGA register file before EVERY trace. Key-write bus leak is
      r=0.60 (sum key-byte HW, prof16sc @621 / confirm_hwin @161). The
      per-column "key POIs" sat exactly on the key-write samples — they
      were echoes of the key LOAD, not ASCON crypto. ***
   4. Fixed-key control (main_live, 3000 tr, key const): per-column
      true-label max|r| = 0.045-0.065, ALL below the 0.079 null; the 4
      key hypotheses give IDENTICAL correlations (no discrimination).
      => NO first-order crypto leakage at VCCINT in any model at any
      voltage. MANDATORY GATE for any future PA claim: the leak must
      survive with key held constant (only nonce varying).
   Verdict doc: board_session/verdict_hwin_hd.md

B. Clock-glitch FI arm — single-bit faults REACHABLE but structurally
   unusable for full-key DFA on this core.
   1. This session FOUND the round-11 single-bit faults the Sep-4 session
      said were unreachable: num_glitches=1, eo=41, off=0/3359, w=67 on
      RANDOM nonces. 12+ clean faults localized to exact (col, bit)

   2. BUT each nonce faults EXACTLY ONE column, deterministically:
      - full eo sweep (30-50), fine offset sweep (0-3360 in ~60 steps),
        width sweep (20-220), 5 MHz clock, 0.92 V: nonce 8b4ae5...
        ALWAYS column 41, nothing else.
      - different nonces fault different single columns; ZERO nonces
        fault at 2 eo or 2 columns in the hunt data.
   3. Why full-key DFA is impossible: recover_key needs all 64 columns of
      ONE nonce's round-11 state (rebuild 5-word state, propagate to tag).
      One-column-per-nonce across different states can never assemble it.
      Burst (num_glitches=4) hits multiple columns but as multi-round
      superposition — 0/400 match single-bit, no 2-fault (r11+r12) model

      nonce bits (best |r|=0.49 vs nonce bit 53), not the key — the
      documented nonce-shortcut trap, not an FSA key oracle.
   => FI full-key DFA blocked by fault-location determinism (measured
      structural property): glitch faults are nonce-selected single-column.
